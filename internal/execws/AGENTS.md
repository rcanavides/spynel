# Execution Workspace DOX

## Purpose

- Own the execution-plane boundary between durable workflow state and isolated Git workspaces: git-worktree lifecycle, canonical result capture, system-owned checks, and ff-only target integration.

## Local Contracts

- The control plane (`.spynel/tasks`, `.spynel/goals`, `.spynel/runtime/*`, `refs/spynel/launches/*`, the target ref) is durable authority. No durable fact may depend on a worktree surviving; worktrees, provider processes, check processes, ignored build outputs, and the temporary capture index are execution plane only.
- `Backend` owns workspace lifecycle, `Workspace` owns capture/verify/check inside one workspace, and `Integrator` owns repository target movement. The Manager never owns raw Git implementation, and provider process lifecycle stays in `internal/harness`.
- Workspace identities are `ws-` plus 26 lowercase base32 characters, independent of task, launch, and path. Worktrees live at `.spynel/worktrees/<WorkspaceID>` as detached locked Git worktrees with no user-facing task branches.
- Preflight fails closed for a new isolated implementation claim when git is missing, Git is older than 2.25, the root is outside a worktree, the repository is bare, the root target HEAD is detached, or `.spynel` is tracked. There is never a silent fallback to shared mode; the document stays eligible and unclaimed with the reason surfaced. The report freezes repo top-level, the relative root, the target ref, and the target old SHA.
- A workspace root below the repository top maps the provider directory to `<worktree>/<relative-root>`; OS paths use `filepath` and Git pathspecs use `filepath.ToSlash`.
- The Git runner uses `exec.CommandContext` with explicit arguments and no shell, scrubs GIT_DIR, GIT_WORK_TREE, GIT_INDEX_FILE, GIT_OBJECT_DIRECTORY, GIT_ALTERNATE_OBJECT_DIRECTORIES, GIT_COMMON_DIR, GIT_NAMESPACE, GIT_CEILING_DIRECTORIES, and every `GIT_CONFIG_*` variable, sets GIT_TERMINAL_PROMPT=0 and GIT_OPTIONAL_LOCKS=0, disables hooks through an empty `core.hooksPath`, disables commit signing, and bounds stdout and stderr.
- Prepare is idempotent for the same WorkspaceID and StartSHA, reusing only a registered clean worktree at the exact SHA; conflicts fail closed with ErrWorkspaceConflict. Remove tolerates partially completed cleanup (unlock, remove --force, prune) and never deletes directories outside the exact owned workspace path.
- Capture at provider terminal builds the canonical result from working content through a Spynel-controlled temporary index (`read-tree base`, `add -A -- .` from the provider view, `write-tree`), rejecting merge/cherry-pick/rebase/revert/bisect states, gitlink entries, and forbidden `.spynel` result paths. The agent's Git HEAD and index are never authority: agent commits, resets, and checkouts are recorded as `agent_head_moved` evidence while the canonical commit still parents to the captured base. Deterministic author/committer identity and timestamps make retries reproduce the same SHA.
- Unchanged content captures as changed=false with no result commit or ref. Changed content publishes the create-only ref `refs/spynel/launches/<LaunchID>/result` via zero-old update-ref CAS: an identical existing ref or an independently validated equivalent canonical result (same tree, same base parent) is adopted, and the existing ref SHA becomes the authoritative returned result SHA; anything else fails closed with ErrCaptureRejected{ref_conflict}. The workspace then moves to that authoritative result and VerifyAt must prove a clean nonignored tree before result evidence is recorded.
- Checks are Spynel-owned evidence against the exact result SHA: the workspace is verified at R before and after each check, a mutated nonignored source yields outcome=mutated and stops remaining checks, ignored build outputs are tolerated, and checks never create result commits. Commands run without a shell; Unix kills the whole descendant process group on timeout or cancellation while Windows uses the accepted direct kill. Full combined output is SHA-256 streamed, with a retained 128 KiB tail under `.spynel/runtime/launches/<LaunchID>/checks/<id>.log`.
- Check evidence binds the launch, result SHA, and definition digest. Definition and set digests are deterministic across processes.
- Integration takes the repository-global cross-process lock at `.spynel/runtime/locks/integration.lock` plus the backend's process-local mutex, requires the target to still equal the captured old SHA and the result to be a fast-forward of it, then applies one mechanism: a working-tree-aware `git merge --ff-only` in the root checkout (blocked as target_dirty when user edits would be overwritten, never resetting them), a CAS `git update-ref` when the target is checked out nowhere, and ErrIntegrationBlocked{checked_out_elsewhere} when another worktree holds it. A target already at the result is observed without a second movement. Never rebase, never force, never merge diverged history, never create merge commits.
- C9-F is not sandbox security: the trust boundary protects workflow integrity against stale callbacks, wrong SHAs, wrong workspaces, races, crashes, agent commits treated as authority, and non-ff integration — not against malicious same-user agents.
- Developer concurrency remains 1 and the shared-checkout writer gate remains in force until later milestones change it.
