# Harness Adapter DOX

## Purpose

- Own the provider-neutral harness interface, catalog/factories, transactional supervisors and the unified multi-provider Runtime lifecycle, and Codex, Claude Code, Agent Zero CLI, Pi, and ACP process adapters.
- Keep role routing provider-neutral: callers select logical roles such as chat, developer, reviewer, notification, or heartbeat; concrete provider names remain confined to harness configuration and adapters.
- Keep provider retirement and structural replacement fail-closed and idle-only. Each normalized catalog ProviderID owns at most one stable Supervisor and one exclusive session-file path; matching roles share that Supervisor.

## Local Contracts

- Runtime is the sole production lifecycle owner for chat, developer, reviewer, notification, and heartbeat. RuntimeSpec contains providers and role mappings; RoleChat defines the primary and unspecified roles fall back to it. Validate normalized IDs, mapped providers, routed custom ACP configuration, and unique session-file ownership before construction/publication. Operational role targets remain stable and never expose provider lifecycle methods. No RoleSet or separate routed lifecycle exists.
- Runtime binds admitted session keys to their exact Supervisor, retaining that owner while reservations/admissions or logical work remain. Re-probe a zero-admission binding outside the mutex and revalidate its identity before reuse; stale idle bindings must resolve the current role, never resurrect a retired provider. Admission reservations span workflow claims, job attribution, and dispatch without persisting ownership in leases. Bound controls, interruption, activity, thread lookup, conversation admission, and resets retain the exact owner across role remaps.
- Serialize Start, Close, and reconciliation using lifecycle reservations, never a mutex held over provider work. Reconciliation fences only affected providers, rejects retirement while bindings, logical turns, or operational lifecycle work remain, prepares structural changes through Supervisor.PrepareChange/Commit/Abort, and publishes role mappings atomically. Unchanged providers retain their Supervisor and process. Added providers start before publication; routed startup failure remains explicitly unavailable without chat fallback or shutdown of healthy providers, and later reconciliation retries the same Supervisor. Chat startup errors retain the server's existing unavailable-start behavior. Close retires each unique Supervisor once.
- Forward Supervisor broadcast Readiness into Runtime's close-and-replace broadcast, including topology changes; multiple observers independently recheck current state. This is wakeup forwarding, not another availability state machine. Never hold Runtime's mutex across Supervisor calls, provider I/O, emitters, or application persistence callbacks. Memory-only admission reservations provide exact JobDetails.Provider attribution without Lease.Provider or persisted execution ownership.
- Keep application and orchestration code harness-neutral; adapters map native events into the common response and follow-up contract.
- Supervisor structural changes reject active logical executions and queued continuations unchanged, then fence new admissions and drain transient provider calls through their return before candidate construction. Preparation and draining honor the preparation context. Existing Send and SendConversation admissions wait through the structural fence with their caller context and use the adapter published by commit or retained by abort; Start also waits for settlement. Controls, discovery, inference/configuration changes, and session resets fail closed while fenced. Interrupt while fenced and idle returns false without provider I/O. Commit publishes only in-memory state and transfers the previous adapter to the caller for retirement outside locks; abort cleans up only the candidate before restoring admission. Before service startup, preparation remains configuration-only. Close waits for active preparation, then owns and cleans up any abandoned prepared candidate and the current adapter without requiring caller settlement. Abort after commit or Close is a safe no-op, and Commit after settlement publishes nothing. Lifecycle reservations span provider I/O without retaining the supervisor mutex, and inference persistence shares the dispatch barrier so callbacks may inspect state without changing snapshot ordering. Existing per-session send/control serialization remains intact. Lifecycle tests use fixture channels and testing/synctest quiescence to establish blocked operations without timing assumptions.
- Distinguish temporary structural fencing (`ErrProviderFenced`) from absent/closed/start-failed providers (`ErrProviderUnavailable`, retaining the startup cause); pass admitted provider execution errors through unchanged. Keep the legacy `ReadyEvents` edge for existing callers and expose versioned close-and-replace `Readiness` snapshots for independent observers; observers acquire a new snapshot after each wakeup, and readiness is a signal to recheck state, never proof of availability.
- Codex maps strictly boolean `error.willRetry: true` to nonterminal `reconnecting` status, retaining diagnostics in captured events. Only nonempty agent-message, reasoning, or plan deltas for the exact active turn restore `running`; tool output and generic activity do not establish upstream recovery. Missing/false/malformed retry flags remain errors. Serialize admission, deferred replay, live notifications, and transport failure through callback publication; publish admission first and reject another turn's late events. Transport failure also fences pending admission so a successful RPC reply cannot resurrect an exited provider.
- Resume Codex threads with `excludeTurns: true`: Codex retains its conversation context, while Spynel consumes only thread identity and its own bounded history. Any resume failure preserves the saved session and rejects dispatch instead of silently creating a replacement conversation. Keep the shared 16 MiB message bound; overflow and EOF close provider stdin as well as cancelling the subprocess so npm-launched native children receive EOF, fail pending/active work, and remain visibly unavailable through the supervisor until explicit restart or successful reconfiguration. Overflow diagnostics inspect only a bounded envelope prefix to identify a known notification or the correlated pending RPC, report unavailable metadata explicitly, and name the message-size limit and reconnect action without exposing payloads, provider IDs, arbitrary method strings, or replaying interrupted requests.
- Declare native-steer versus queued follow-up behavior explicitly, fence active executions, and invoke durable iteration reservation exactly once immediately before accepted provider delivery.
- Expose the provider-neutral new/steered/queued conversation admission classification at the same session fence so application correlation can cover consolidated terminal responses exactly.
- When an ordinary queued follow-up replaces an emitter, deliver its predecessor's continuing result followed by an explicit done-status release. This closes every request and balances application/channel activity without claiming logical completion. Orchestrator controls that preserve their emitter do not release it.
- An interruption attempt cancels not-yet-dispatched ordinary follow-ups with a terminal error per request, including every emitter in a dequeued batch. Capture the cancellation generation when removing queued work, preserve it through batching, and reject stale dispatch even if a successor turn is active. Queued controls retain their shared emitter; only the provider owns that execution's terminal event. Failure to interrupt the active provider does not restore already-cancelled queued requests.
- Order forward-looking model commits and dispatch snapshots under one supervisor fence. Never mutate an already-admitted provider turn; native steering remains part of that turn, while queued continuations and later top-level turns snapshot the newest model at their own provider-dispatch admission.
- Extend that fence to reasoning effort and service mode. Catalog metadata declares effort support for Codex, Claude, and Pi. Their model and effort values pass through to the provider without requiring discovery or catalog membership; validate bounded effort syntax at the shared boundary and let provider errors report unsupported manual choices. Codex reads per-model effort/service tiers for detected choices and passes `effort`/`serviceTier`; service selections still require verified capabilities. Claude passes `--effort`. Pi identifies its current/default model and current thinking level from `get_state`, queries each catalog model's exact RPC thinking levels in a separate no-session process selected by the non-persistent `--model` runtime override, labels a default effort only for the authoritative current model, and passes `--thinking`; never use Pi's persistent `set_model` RPC for capability inspection. Both legacy omitted and explicit Pi efforts reach the provider for validation/clamping. ACP model selection remains supported, but reasoning and speed are unsupported because ACP advertises optional thought choices only after session creation and defines no standard speed category.
- Build commands without shell interpolation, bound scanner/event payloads, surface startup and negotiation diagnostics, and keep portable fixture providers synthetic.
- Keep Agent Zero CLI as the fixed `agent-zero` profile backed by the shared ACP adapter, launch `a0 acp`, and require a bounded successful `a0 acp --check` before reporting it available.
