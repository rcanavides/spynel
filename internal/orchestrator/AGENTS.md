# Markdown Orchestrator DOX

## Purpose

- Own durable task/goal workflows, claims and leases, recovery, review policy, semantic heartbeat, direct notification-agent dispatch, and ordinary delivery reconciliation.

## Local Contracts

- Treat Markdown as source of truth, claim queued phases atomically, fence provider work with phase-specific leases, preserve task-goal round links, and enforce configured transitions and review overlays.
- Isolate scan failures by lease, document, and stage. Log and skip unreadable existing transition candidates while checking later allowed statuses; never treat an unreadable candidate as missing or modify its bytes. Retain the lease and live job when no candidate is readable, collect contextual errors, and continue independent recovery, queues, and final outbox processing. One-shot callers wait for work already dispatched even when the same scan reports unrelated errors; this does not add another reconciliation round.
- Accept an operational ExecutionTarget for the fallback harness; orchestration never owns its Start, Close, or structural reconfiguration.
- Resolve provider work through provider-neutral role routing: implementation and planning use the developer role, independent review uses the reviewer role, task notification agents use the notification role, and semantic heartbeat agents use the heartbeat role. Dispatch, activity, interruption, recovery, idle, and control-continuation checks must resolve the same harness for the admitted role and phase.
- Reserve the selected Runtime execution owner before claiming a queued phase or dispatching work. Every successful durable-work reservation that returns a nonempty `ProviderID` records that exact provider instance in `Lease.Provider` through the existing post-reservation lease save; Markdown never supplies provider identity. A nonempty `Lease.Provider` is authoritative for existing owned recovery and uses `ReserveOwnedExecution` without role or chat fallback; an empty legacy owner uses role-based `ReserveExecution` and adopts its exact nonempty returned instance ID. Exact nonempty owners from the active `.spynel/runtime/leases` records participate in startup and live Runtime topology composition without gaining roles; owner enumeration is read-only, deduplicated, deterministic, and skips an individual malformed or unreadable lease record without mutation while valid owners remain retained. Typed `ErrProviderUnavailable` on an existing durable lease records framework-owned `blocked.reason = provider_unavailable` and `blocked.since` at the first failed reservation of that episode without changing lease state, ownership, heartbeat, recovery count, errors, or workflow Markdown; identical unavailable retries preserve the timestamp and do not rewrite the lease. Clear that block only in the normal save after a successful reservation, and let blocked leases bypass the ordinary `StaleAfter` age gate while retaining inflight, active-provider, and recovery safety checks. `ErrProviderFenced` is transient. Only typed `ErrProviderAbsent` from exact owned admission permits one normal current-role `ReserveExecution` to reassign a durable owner. A successful move requires a concrete nonempty returned `ProviderID` and atomically saves that exact instance, cleared `ThreadID` and `Blocked`, and the recovery ownership/heartbeat update before dispatch; it does not itself increment `RecoveryCount`. Failed replacement admission or an empty ID leaves the old durable lease unchanged and releases any replacement reservation. Unavailable and fenced owners never move, and a role remap alone cannot move a resolvable owner. No fallback list, quota policy, or C11 fallback is implemented. Queued or otherwise unclaimed work remains unblocked, and Markdown front matter cannot create or clear lease blocking. Never silently fall back to chat. Runtime broadcast readiness wakes rechecks independently of other observers. Claimed documents without leases remain outside this blocked-lease behavior.
- Recovery dispatch retires any ended local execution handle and resets the previous execution state and error before admission, preserving the public job number and archived history. Ignore events for retired handles. `recovering` covers restart preparation only: structured provider running evidence or successful admission returns the lease to `processing`, retaining the recovery count and journal. Serialize admission updates with provider events so terminal `awaiting_transition` cannot be overwritten; provider completion still requires durable transition reconciliation and never changes task/goal status by itself.
- Obtain agent-authored timestamps from the current environment clock; waiting requires a concrete external condition, and recovery may not bypass live ownership or required review.
- For every task `done`, `failed`, and `cancelled` transition and every actionable unscheduled `waiting`, directly start one ordinary asynchronous notification-agent job. Re-read and validate enabled notification metadata plus the selected outcome before prompt construction. Supply task evidence exactly once: preserve a safely fitting document in full, otherwise use a deterministic valid-UTF-8 beginning/recent-end JSON projection with an explicit untrusted middle-omission marker, omitted-byte count, and exact JSON-encoded absolute path for inspecting the complete authoritative Markdown. Budget that projection only after rendering the customized template, framework guidance, scope discipline, and persistent notification instructions; retain a documented 4 KiB safety margin below the 128 KiB provider boundary, and reject oversized non-task sections precisely. Supply a shell-safe command with the absolute executable/workspace and exact task origin already filled in, using `--message \"Hello there\"`; direct the agent to change only that message. At render time, omit obsolete delivery paragraphs from preserved workspace overrides while retaining their unrelated custom decision and writing guidance. The agent alone decides and edits task progress with its send, skip, or CLI failure; do not parse provider output or create notification-specific persistence, claims, bindings, results, recovery, or replay. Do not bind semantic-heartbeat guidance to a task origin.
- Admit manual semantic heartbeats through the same scheduler loop and provider fence as timer ticks; provider release after either mode owns the next fixed-delay deadline. The elected primary alone invokes the shared cleanup callback on an eight-hour cadence using the live retention value.
- Heartbeat reminder policy belongs entirely to the agent: it inspects bounded waiting-task progress, judges inactivity and usefulness, invokes the ordinary recent-authorized notification CLI, and journals a send/skip/failure in that task. The manager only triggers the heartbeat and injects this rule; it must not implement reminder queues, timers, thresholds, eligibility, identity links, correlation, acknowledgement, deduplication, contingency branches, or delivery orchestration beyond the ordinary notify primitive. At render time, omit retired read-only, original-origin-only, and action/JSON-result paragraphs from preserved workspace heartbeat overrides while retaining unrelated customized inspection and repair guidance.
- Treat heartbeat harness dispatch as worker admission, not a result protocol. Keep the provider fence through terminal release, ignore every provider payload, and persist no framework heartbeat action, finding, health, incident, escalation, retry, or notification state. The agent uses ordinary Spynel CLI inspection and applicable Markdown workflow contracts to make the smallest evidence-backed repair, journals each durable change itself, and may request the existing serialized orchestrator trigger. Task terminal and actionable unscheduled waiting transitions dispatch their notification agent directly.
- Require application job admission before dispatching task, review, goal, heartbeat, or notification-agent provider work; an admission failure stops that dispatch and follows the owning workflow's ordinary error path. Forward admitted provider-neutral streams to the application job recorder without parsing their text. Archive capture never changes lease, transition, notification, or recovery decisions.
- Run heartbeat and notification agents through the same ordinary provider-neutral job lifecycle: `Send` admits asynchronous work and never implies completion, `Codex turn started` is nonterminal, and the first non-continuing final/error event, cancellation, or bounded timeout ends job ownership exactly once. Keep the complete accepted event stream through that boundary, ignore late/duplicate terminal events, and retain heartbeat cadence/non-overlap as a separate scheduling fence until provider release.
- Serialize terminal-task retention with goal scanning. Keep every settled task linked to any nonterminal goal in the live status folders until that goal reaches a terminal outcome; an incomplete nonterminal-goal index must fail safe by protecting goal-linked tasks.
- Own exactly two fixed workflows under `.spynel/tasks` and `.spynel/goals`, with fixed prompt paths, transitions, and 30-minute/task and two-hour/goal stale thresholds. Do not persist route definitions in configuration, leases, or goal front matter. Task/goal creation prompts, scans, recovery, retention, status, and linked rounds share these canonical folders. Apply scanner interval changes by synchronously resetting the production timer and fence already-selected stale timer generations through the scan lock.
